# MCP access for 0.9.0

Desktop and web expose the same operations to external agents. Disabled until the
owner enables access. Each named connection has its own revocable token, explicit
Torrent Client allowlist, and proposal-only mode by default. Tokens never grant
settings or credential access. HTTP uses bearer tokens; local stdio forwards to
the running application. The server does not contain an LLM or a scheduler.

Agent tools inspect clients, paginated torrents and Library entries, search c411
with category options, prepare Plans, queue and send selected downloads, check and
reseed Candidates, prepare and edit Upload descriptions, and create c411 Drafts.
Publication stays on c411. µTorrent/BitTorrent Classic disk renames still require the existing
per-torrent human workflow and cannot be authorized through MCP.

Mutations become durable proposals unless the owner explicitly enables the
corresponding permission. Torrent removal and deletion always require owner
approval in TorrentLinker. Approval binds the exact operation and configuration;
request IDs prevent repeated submissions. Revocation cancels pending agent jobs.

Download limits apply cumulatively per connection per UTC day, including pending
reservations. Conservative reservations remain after failed/interrupted sends.
Free-space reserves include pending downloads and shared physical disks. Agent
operations use configured folders only. No arbitrary file, URL, SQL or shell tool.

Saved goals record target daily Zen, optional target balance and desired Class.
Progress uses the app's estimates, deduplicating hashes across clients. A goal
never changes the actual c411 Class. Reuploader upload rewards and revival payouts
are not inferred from recurring seed income. Catalogue coverage and estimates
remain provisional. No scheduled optimization in this first implementation.

Acceptance boundaries: owner setup API, job API, browser flows, and real MCP
connections (approved by the user). Verify defaults, allowlists, revocation,
approval binding, duplicate requests, budgets, safe failures, pagination, desktop
coordination, stdio and Streamable HTTP. Preserve existing unrelated warning fix.
