# tr4ker integration inventory

Inspected 2026-11-23 against the working tree. This is a source-code inventory, not evidence of tr4ker capabilities. Live tr4ker observations belong in a separate research note. No application code, session secrets or account data were changed for this inventory.

## Existing support boundary

TorrentLinker already accepts many **Indexers**, but its full tracker experience is still c411-specific. The saved Indexer list, Torznab capability discovery, Prowlarr/Jackett import and automatic Cross-seed are useful starting points. Adding a second entry alone does not enable native Search, Catalogue, Profile, Upload, tracker community or media discovery for that entry.

`Settings.indexer` always returns `C411_ID`; its own docstring says this is the Indexer used for Catalogue, Uploads and everything except Cross-seed. `WebSetup.indexer_for()` dispatches c411 to `Indexer` and every other entry to `TorznabIndexer`. There is no native tracker provider registry in this dispatch. Source: [config.py:90](../../src/torrentlinker/config.py#L90), [config.py:135](../../src/torrentlinker/config.py#L135), [config.py:340](../../src/torrentlinker/config.py#L340), [web/setup.py:311](../../src/torrentlinker/web/setup.py#L311), [web/setup.py:570](../../src/torrentlinker/web/setup.py#L570).

The domain vocabulary intentionally distinguishes an Indexer, a search endpoint, from the tracker website. The present glossary also binds Upload Category, Zen, Class and Owner identity to c411. Full tr4ker support therefore needs an explicit tracker/account selection model and a decision about capabilities that tr4ker does not have. Do not silently apply c411's Zen formula or Upload rules to another tracker. Source: [CONTEXT.md](../../CONTEXT.md), [ADR-0005](../adr/0005-own-catalogue-and-zen-rules.md), [ADR-0024](../adr/0024-automatic-cross-seed-across-many-indexers.md).

## Authentication and browser companion

The companion intentionally performs authenticated work in the signed-in tab. `collect.js` never reads cookies/storage; `read.js`, `descriptor.js` and `community.js` use same-origin fetch, fixed routes, account checks and redirect rejection. Session and CSRF tokens stay in the tab. This is an existing design to preserve when implementing tr4ker. A temporary cookie used for authorized local research should not become a committed fixture or the production connection model by accident. Source: [collect.js:1](../../src/torrentlinker/companion_extension/collect.js#L1), [read.js:1](../../src/torrentlinker/companion_extension/read.js#L1), [descriptor.js:1](../../src/torrentlinker/companion_extension/descriptor.js#L1), [community.js:1](../../src/torrentlinker/companion_extension/community.js#L1).

The manifest currently grants only c411 and local app hosts. `background.js` queries/opens only c411 tabs. Profile snapshots require `source === "https://c411.org"`; pairing and community account operations enforce the same source. An origin addition alone is insufficient: command dispatch, account binding, validation, permissions, browser UI text and persisted profiles must also select the tracker. Source: [manifest.json:8](../../src/torrentlinker/companion_extension/manifest.json#L8), [background.js:99](../../src/torrentlinker/companion_extension/background.js#L99), [background.js:269](../../src/torrentlinker/companion_extension/background.js#L269), [profile_workspace.py:145](../../src/torrentlinker/profile_workspace.py#L145), [profile_workspace.py:398](../../src/torrentlinker/profile_workspace.py#L398), [profile_workspace.py:528](../../src/torrentlinker/profile_workspace.py#L528).

Record cookie **names and attributes**, authentication expiry/renewal behavior, logged-out status/redirect behavior, CSRF location/header and whether a supported API key exists. Keep actual cookie values, CSRF values, API keys and passkeys out of research files. Capture whether the session is needed only for discovery or also descriptor download and profile reads.

## Search, details and descriptors

The reusable `Candidate` has title, size, descriptor URL, seeders, optional infohash, details URL, category IDs, publication time and verified metadata. `SearchQuery` represents Torznab modes and external IDs. `TorznabIndexer` implements caps/search/fetch/pacing/redaction, but has no `torrent_json`, native search categories, upload drafts, profile or catalogue methods. Its `search()` also lacks the `cached=` parameter used by the current RSS service, so it is not a complete drop-in replacement for the primary Indexer. Source: [indexer.py:127](../../src/torrentlinker/indexer.py#L127), [indexer.py:163](../../src/torrentlinker/indexer.py#L163), [torznab.py:64](../../src/torrentlinker/torznab.py#L64), [feeds.py:382](../../src/torrentlinker/feeds.py#L382).

The native search implementation reads c411 category/facet structures, parses its listing schema and generates c411 detail URLs. The Indexer has c411-only methods for `/api/torrents`, `/api/torrents/{hash}`, `/api/categories`, filter/category options and `/api/torrents/by-tmdb`. Adult content adds separate c411 session-read handling. Source: [indexer.py:487](../../src/torrentlinker/indexer.py#L487), [indexer.py:490](../../src/torrentlinker/indexer.py#L490), [indexer.py:565](../../src/torrentlinker/indexer.py#L565), [indexer.py:614](../../src/torrentlinker/indexer.py#L614), [torrent_search.py:37](../../src/torrentlinker/torrent_search.py#L37), [torrent_search.py:139](../../src/torrentlinker/torrent_search.py#L139), [torrent_search.py:222](../../src/torrentlinker/torrent_search.py#L222).

`DetailsWorkspace.load()` validates a 40-character hash and calls `torrent_json`; `parse_details()` expects c411's description, metadata/NFO, path-array files, uploader/team, swarm counts, category/options, trust and TMDb data. The safe HTML/image rendering can remain useful behind another payload adapter. Native numeric IDs must be retained separately from infohashes if tr4ker uses them. Source: [details_workspace.py:30](../../src/torrentlinker/details_workspace.py#L30), [torrent_details.py:143](../../src/torrentlinker/torrent_details.py#L143), [torrent_details.py:255](../../src/torrentlinker/torrent_details.py#L255).

Descriptor inspection should establish v1/v2 support, private flag, `info.source`, piece-size rules, tracker URLs and whether the downloaded torrent changes from a pre-upload torrent. Read descriptor bytes locally without announcing them to a Torrent Client during research. c411's existing API/session download paths and limits live in [indexer.py:348](../../src/torrentlinker/indexer.py#L348), [companion_downloads.py:129](../../src/torrentlinker/companion_downloads.py#L129) and [descriptor.js](../../src/torrentlinker/companion_extension/descriptor.js).

## Reseed and Cross-seed

File-tree matching, path layouts, protected data, Torrent Client operations and 100% Verification are largely independent of tracker website schemas. Cross-seed already persists an `indexer_id`, searches external IDs when supported and dispatches through `indexer_for`; it only uses c411 category settings and Catalogue-first optimization for c411. Source: [crossseed.py:158](../../src/torrentlinker/crossseed.py#L158), [crossseed.py:278](../../src/torrentlinker/crossseed.py#L278), [crossseed.py:368](../../src/torrentlinker/crossseed.py#L368), [reseed.py:64](../../src/torrentlinker/reseed.py#L64), [ADR-0024](../adr/0024-automatic-cross-seed-across-many-indexers.md).

Tracker recognition affects whether a Local Item is Seeded and which torrents contribute to estimates. `is_indexer_torrent` matches same-site hosts and has a c411 alternate-host special case; `indexer_torrents` also accepts known hashes and the generic Reseed tag. With multiple fully supported trackers, verify these shortcuts do not assign one tracker’s torrents to another. Source: [zen.py:283](../../src/torrentlinker/zen.py#L283), [seeding.py:77](../../src/torrentlinker/seeding.py#L77), [library.py:163](../../src/torrentlinker/library.py#L163).

## RSS, Catalogue, Plans and media

RSS subscriptions currently select query/categories/client/folder, not an Indexer. Polling is a paginated extended Torznab search, not a general arbitrary RSS-URL importer. Enrichment calls `torrent_json` and reads c411 `tech`/`metadata`; it distinguishes verified IDs/attributes from guesses in titles. tr4ker mapping must preserve that distinction. Source: [feeds.py:100](../../src/torrentlinker/feeds.py#L100), [feeds.py:382](../../src/torrentlinker/feeds.py#L382), [feeds.py:922](../../src/torrentlinker/feeds.py#L922), [feed_control.py:28](../../src/torrentlinker/feed_control.py#L28).

Catalogue sync contains c411 download/detail URLs, native-to-Torznab category translation, c411 enumeration limits, count/prune logic, a packaged snapshot and a Zen Lab fallback. Those sources cannot seed tr4ker’s Catalogue. Catalogue, crawl, unavailable-torrent and category-options tables are keyed by hash/category/subcategory without an Indexer namespace. A same-hash torrent on two trackers or a reused native category ID must not overwrite account-specific descriptor URLs, availability or category options. Source: [catalogue_sync.py:34](../../src/torrentlinker/catalogue_sync.py#L34), [catalogue_sync.py:92](../../src/torrentlinker/catalogue_sync.py#L92), [catalogue_sync.py:381](../../src/torrentlinker/catalogue_sync.py#L381), [catalogue_sync.py:666](../../src/torrentlinker/catalogue_sync.py#L666), [store.py:94](../../src/torrentlinker/store.py#L94), [store.py:129](../../src/torrentlinker/store.py#L129).

The Zen model is explicitly a dated c411 rules table, with classes, bonuses, caps and rounding. Profile parsing is likewise c411-specific. For tr4ker, establish actual ratio/download-credit/freeleech/seed-time/HnR rules and supported reward calculations before exposing a Plan as an economic recommendation. An unsupported reward feature needs an explicit capability/UI decision. Source: [zen.py:1](../../src/torrentlinker/zen.py#L1), [profile.py:1](../../src/torrentlinker/profile.py#L1), [seeding.py:100](../../src/torrentlinker/seeding.py#L100).

Media's tracker discovery and upgrade rows explicitly use c411 latest listings, Catalogue and TMDb lookups and generate c411 URLs. Local playback itself is separate. Capture work-level IDs and episode scope from tr4ker so media discovery, upgrade scoring, RSS replacement and Requests choose compatible releases. Source: [media_tracker.py:108](../../src/torrentlinker/media_tracker.py#L108), [media_tracker.py:251](../../src/torrentlinker/media_tracker.py#L251), [media_tracker.py:297](../../src/torrentlinker/media_tracker.py#L297), [media_tracker.py:421](../../src/torrentlinker/media_tracker.py#L421).

## Uploads and tracker updates

Upload profiles are currently profiles of c411 categories. Their subcategory enums, format/naming rules, warnings/refusals, NFO/description generation, options and existing-release lookups require tr4ker-specific rules. The torrent maker uses c411's piece-size table and hard-codes `info.source = "C411"`. Its draft JSON and `/api/user/drafts` client are c411-specific. Source: [upload.py:49](../../src/torrentlinker/upload.py#L49), [upload.py:284](../../src/torrentlinker/upload.py#L284), [upload.py:615](../../src/torrentlinker/upload.py#L615), [upload.py:623](../../src/torrentlinker/upload.py#L623), [upload.py:785](../../src/torrentlinker/upload.py#L785), [indexer.py:645](../../src/torrentlinker/indexer.py#L645).

The Local Draft Queue is a useful review/approval foundation but its remote result and uncertain-send checks mention c411. Preserve revision-bound review, idempotency and uncertainty handling when adding another destination. Existing ADR-0011 reserves publication for the user after creating a remote Draft. A tr4ker implementation that publishes outright would change that decision and should be treated explicitly. Research can inspect forms and documented request schemas without submitting an Upload. Source: [upload_queue.py:52](../../src/torrentlinker/upload_queue.py#L52), [upload_queue.py:98](../../src/torrentlinker/upload_queue.py#L98), [ADR-0011](../adr/0011-uploads-start-as-c411-drafts.md).

Announce update previews and application explicitly recognize c411 hosts/passkey paths and use the primary saved announce. Scope these operations by tracker/account before supporting tr4ker updates. Source: [tracker_updates.py:33](../../src/torrentlinker/tracker_updates.py#L33), [tracker_updates.py:77](../../src/torrentlinker/tracker_updates.py#L77), [tracker_updates.py:95](../../src/torrentlinker/tracker_updates.py#L95), [tracker_updates.py:396](../../src/torrentlinker/tracker_updates.py#L396).

## Profile, tracker community and Community Site

Profile API and companion snapshots currently model c411 Zen/class/level, detailed upload/download statistics, active-seed counts and a Zen ledger. Stable account IDs, nullable fields, units and timestamps need explicit tr4ker mapping. The existing collector rechecks account identity before and after reading. Source: [profile.py:42](../../src/torrentlinker/profile.py#L42), [profile.py:104](../../src/torrentlinker/profile.py#L104), [collect.js:59](../../src/torrentlinker/companion_extension/collect.js#L59).

Tracker community actions are broader than comments: c411 trust votes, general/class chat, seed-based eligibility, limits/cooldowns, duplicate detection and receipts are implemented through the companion. Discover whether equivalents exist on tr4ker and keep absent actions disabled. Do not post test comments/votes/messages to establish schemas. Source: [community.py:61](../../src/torrentlinker/community.py#L61), [community.js:32](../../src/torrentlinker/companion_extension/community.js#L32), [community.js:95](../../src/torrentlinker/companion_extension/community.js#L95).

The separate TorrentLinker Community Site links an app using the primary profile/API credential, and `ProfileWorkspace.community_account()` currently accepts only c411 identity. Full second-tracker support must namespace verified tracker membership and resolve linking multiple tracker accounts to one Site Account. Source: [community_site.py:108](../../src/torrentlinker/community_site.py#L108), [profile_workspace.py:528](../../src/torrentlinker/profile_workspace.py#L528), [ADR-0023](../adr/0023-a-community-site-that-never-names-the-tracker.md).
