TorrentLinker 0.10.0 ajoute un **Assistant intégré**, sur ordinateur comme sur le web, pour discuter avec un modèle et programmer des tâches. Les uploads disposent aussi d'une **file de brouillons locaux** pour relire les présentations avant de les envoyer à c411.

## Discuter avec un modèle dans TorrentLinker

Le nouvel onglet **Assistant** permet de créer des connexions nommées et de choisir le modèle utilisé pour chaque discussion.

- Modèles locaux via **Ollama**, **LM Studio** ou un serveur compatible OpenAI.
- Fournisseurs API : **OpenAI**, **Anthropic**, **Google Gemini**, **Mistral** et **OpenRouter**.
- Liste des modèles, saisie manuelle de leur identifiant et test des appels d'outils.
- Historique des échanges, outils appelés, propositions et résultats.

L'Assistant utilise les mêmes opérations et contrôles que MCP : recherches, Plans, téléchargements, gestion des torrents, remises en seed et préparation d'uploads. Il fonctionne directement dans TorrentLinker, sans devoir copier un jeton MCP dans une autre application.

Exemple : « Actualise mon client NAS. Prépare un Plan de trois ebooks maximum, pour moins de 30 Mio. Montre-moi les gains de Zen estimés et les dossiers de destination avant de proposer les téléchargements. »

TorrentLinker ne fournit pas de modèle. Un serveur local doit être démarré et accessible ; les fournisseurs API peuvent facturer les requêtes. La qualité des résultats dépend du modèle choisi et de sa capacité à utiliser les outils.

## Programmer des tâches

Dans **Assistant → Automatisations**, choisissez les clients autorisés et une fréquence : toutes les X minutes, chaque jour ou chaque semaine, avec le fuseau horaire souhaité.

- Les nouvelles tâches sont désactivées au départ. Vérifiez la prochaine exécution et essayez **Exécuter maintenant** avant de les activer.
- L'actualisation des torrents et du Catalogue peut fonctionner sans modèle.
- Les tâches avec modèle peuvent analyser vos torrents, préparer des Plans ou rédiger des présentations d'uploads.
- L'application de bureau ou le serveur web doit rester ouvert. Une tâche interrompue ou en échec ne se relance pas automatiquement.

Le mode **Propositions uniquement** reste le choix initial. Vous pouvez autoriser certaines actions dans les limites configurées : clients accessibles, budget quotidien de téléchargement, nombre de torrents et réserve d'espace libre. Le retrait de torrents, la suppression de fichiers et l'envoi d'un brouillon à c411 nécessitent toujours votre approbation.

## Rechercher les informations d'un upload

La recherche Web s'active séparément pour chaque discussion ou tâche. Elle peut utiliser **Brave Search** ou **SearXNG**, lire une page publique, récupérer des métadonnées et vérifier un lien d'image. Les recherches de films et séries utilisent la clé TMDb configurée ; Open Library est disponible pour les livres.

Exemple : « Choisis un film sans correspondance dans ma Bibliothèque. Vérifie son identité, trouve un synopsis et une image avec leurs sources, puis prépare la présentation dans la file locale pour ma relecture. Ne l'envoie pas à c411. »

Relisez les sources, les caractéristiques techniques et les règles de catégorie. Les essais avec un modèle local ont confirmé le fonctionnement des outils, mais aussi des erreurs possibles dans les présentations. Un texte généré doit être vérifié avant envoi.

## Une file locale pour relire les brouillons

Le bouton **Enregistrer dans la file locale**, dans Upload, conserve la présentation dans TorrentLinker. Cette file est disponible sur ordinateur et sur le web, et survit aux redémarrages.

- Relisez et modifiez le titre, l'image, la description et le NFO avant l'envoi.
- L'enregistrement local ne crée pas de torrent, n'envoie rien à c411 et ne lance aucun seed.
- Les tâches automatisées déposent leurs présentations dans cette file pour votre relecture.
- MCP peut lister, modifier et retirer ces brouillons, puis proposer leur envoi à c411.
- L'approbation porte sur la version enregistrée. Une modification invalide une ancienne demande d'envoi.
- Les fichiers sont contrôlés à nouveau avant l'envoi. Un résultat incertain impose de vérifier c411 avant d'autoriser une nouvelle tentative, afin d'éviter les doublons.

Retirer un brouillon local conserve les fichiers et un éventuel brouillon déjà créé sur c411. La publication finale reste manuelle sur le site. L'ancienne action MCP `upload-draft` enregistre désormais dans la file locale ; l'envoi explicite utilise `upload-send`.

## Validation

La validation locale comprend **1 051 tests réussis**, dont les parcours dans un vrai navigateur, ainsi que les contrôles de types, de traduction et de démarrage. Les tests de file locale couvrent la conservation après redémarrage, la séparation des clients, les modifications de présentation, les approbations périmées et les envois incertains. Les essais d'envoi de brouillons utilisent un service c411 simulé.

Les protocoles des fournisseurs sont testés avec des réponses simulées. Un modèle local a aussi été essayé dans un environnement isolé pour les appels d'outils, les Plans et la rédaction de présentations par catégorie.
