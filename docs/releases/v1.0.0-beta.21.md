# TorrentLinker 1.0.0-beta.21

Cette version harmonise Upload et les paramètres d’accès des agents sur le bureau et le web. Elle ajoute aussi le choix de l’utilisateur Docker au démarrage pour les installations NAS.

## Upload et paramètres

- Upload s’ouvre sur les brouillons locaux, avec la liste et l’éditeur côte à côte. Les deux interfaces partagent les sections Détails, Fichiers et NFO, Description, Illustration et Relecture.
- Enregistrez localement, puis confirmez la révision dans Relecture avant l’envoi à c411. Modifier le brouillon efface cette confirmation. La publication finale reste manuelle sur c411.
- L’accès des agents reste dans Paramètres. Vous pouvez consulter les connexions existantes, leurs clients torrent autorisés et leurs limites, créer ou révoquer une connexion, et enregistrer son jeton dans un fichier. Le jeton n’est affiché qu’à sa création.

## Docker et NAS : PUID/PGID

Le mode facultatif d’initialisation root permet d’utiliser l’image publiée avec, par exemple, `PUID=1001` et `PGID=100`, sans reconstruire l’image. Depuis le dépôt, après préparation du mot de passe :

```bash
TL_IMAGE_TAG=1.0.0-beta.21 PUID=1001 PGID=100 docker compose \
  -f compose.yaml -f deploy/compose.identity.yaml up -d --pull always
```

Le démarrage non-root reste le comportement par défaut. La surcharge autorise uniquement les quatre capacités nécessaires à l’initialisation, corrige les propriétaires sous `/config`, puis abandonne les privilèges avant de lancer l’application et Tini. Les liens symboliques, fichiers avec plusieurs liens physiques et montages imbriqués sont ignorés. Réservez `/config` aux données de l’application et montez les médias ailleurs.

Un `user: "UID:GID"` explicite conserve ses groupes supplémentaires et utilise une configuration préparée par l’administrateur. Les chemins de configuration personnalisés restent pris en charge. Les identifiants invalides ou les capacités manquantes arrêtent le démarrage ; une erreur de correction affiche un avertissement, sans repli vers une application exécutée en root.

Tini est inclus pour transmettre les signaux d’arrêt et récupérer les processus orphelins, même sans `docker run --init`. Voir les [instructions Docker](https://github.com/Vietnoirien/TorrentLinker/blob/v1.0.0-beta.21/docs/guide/fr/web-docker.md) et l’[issue #43](https://github.com/Vietnoirien/TorrentLinker/issues/43).

## English

Upload now shares a local-draft workspace and the same editor sections across desktop and WebUI. Sending requires saving and confirming the current revision in Review. Agent access and connection management stay inside Settings, with token export and revocation controls.

Docker adds opt-in runtime PUID/PGID support without rebuilding the published image. The default stays non-root. Initialization repairs only `/config`, skips links and nested mounts, then drops privileges before starting the application and Tini. Existing explicit non-root users and custom configuration paths remain supported. Use the versioned image above or `beta`; the older stable `latest` image does not include this feature. See the [Docker guide](https://github.com/Vietnoirien/TorrentLinker/blob/v1.0.0-beta.21/docs/guide/en/web-docker.md).

Cette version est une préversion. La version stable reste 0.12.2.
