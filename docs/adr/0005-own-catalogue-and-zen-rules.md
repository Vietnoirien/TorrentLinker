# A local Catalogue with direct c411 updates, and our own Zen rules

Revised on 2026-10-22 with the user's approval. Torznab repeats its last page after roughly 600 results per query. c411's JSON listing reaches further but clamps at 100 pages of 100 torrents, so neither endpoint alone establishes whole-Catalogue coverage. The investigation is recorded in [the research note](../research/full-catalogue.md).

Use Zen Lab's public metadata snapshot to bootstrap the local Catalogue. It is an undocumented third-party source with unknown upstream freshness and coarse category assignments, so it is a baseline rather than proof of a complete or current c411 catalogue. Import it anonymously with a separate HTTP client, at most once per day when the user requests a Plan or a Catalogue fetch. Never send a c411 key or cookies to Zen Lab or use its grab endpoint.

Refresh new torrents in the Plan's categories directly through c411's JSON listing at the shared polite rate limit. The explicit full-Catalogue action can split broad listings by native subcategory and resume historical page positions. Report remaining paging limits. Direct c411 metadata takes precedence over snapshot values, including more specific category assignments.

The user revised the Plan policy on 2026-10-22 after per-torrent metadata checks blocked planning at roughly four seconds per request. Build Plans from cached metadata and label their Zen and note estimates provisional. Do not call c411's per-torrent metadata endpoint to prepare or rerank a Plan. A broad snapshot category is usable when its parent category is selected, but cannot establish membership in a narrower subcategory. After torrents are added, read qBittorrent's swarm counts in one lightweight periodic refresh and recalculate the Seeding view. Unknown swarm counts retain the cached estimate until the tracker responds. Store observed seeder counts for future Plans without treating them as confirmation of the snapshot's size or category. The user can stop a Catalogue update and plan with the data already fetched.

All .torrent downloads still use c411 directly with the user's key. Snapshot rows store only a key placeholder in the direct c411 download URL. Other Indexers retain the Torznab crawl.

The Zen rules are our own implementation in one module, as a data table dated with its source. The size weight, the division by 7, prorating by seed time with a 30-minute minimum, Tanker class bonuses and the tree's +5% are confirmed by c411's official guide. The Swarm Keeper guide excerpt supplied on 2026-10-22 also confirms its seed-age and size/seeder tables, and the category base of 1.00 except XXX at 0.50. This base is added to the note before weighting, rather than multiplied by the age and rarity bonuses. Other Classes' category bases remain unconfirmed and default to 1.00. Zen Estimates are still shown as estimates.
